# js_ydlp v2.0.0-rc-1 - The First Big Release

So, here it is, the first release candidate for js_ydlp (2.0.0-rc-1).

To put it simply, this is a media downloader built in 100% pure Vanilla JS (Node.js ESM, zero external runtime dependencies, no bloated node_modules). It's not trying to clone every single obscure site from yt-dlp, but it's BASING its entire architecture on it, focusing strictly on the ones that actually matter today: YouTube, TikTok, and direct links.

Here is basically everything it can do:

---

### What's in this release:

1. Super intuitive API (one-liners and dual naming):
   - You don't have to instantiate big classes if you just want a file; you can just run one-liners directly:
     * `download('https://...', { output: 'video.mp4' })`
     * `downloadMusic('https://...', { output: 'song.mp3' })`
     * `extractInfo('https://...')` (if you only want the metadata, duration, formats, etc., without downloading anything)
     * `listFormats('https://...', true)` (prints out the full table of resolutions, FPS, and codecs, just like yt-dlp -F)
     * `downloadSeparate('https://...', { videoFormat: 'bestvideo', audioFormat: 'bestaudio' })` (if you want the video and music separated as two files)
     * `downloadImage('https://...', 'cover.jpg')` (to grab thumbnails or images directly)
     * `getLyrics('...')` and `getMetadata('...')`
   - You can also import `ydlp` as default, which works both as an object (`ydlp.download(...)`) and as a factory (`const client = ydlp({ quiet: true })`).
   - And the best part: it supports both camelCase and snake_case for literally everything (so whether you write `output` or `outtmpl`, `skipDownload` or `skip_download`, `continueDl` or `continuedl`, `onProgress` or `progress_hooks`, it just works).
   - Also has a fluent builder if you prefer chaining things (`new YoutubeDL().output('...').format('best').recode('mp4').onProgress(cb)`).

2. TikTok (No watermark, WAF bypass, and auto H.264):
   - Grabs clean videos with NO watermark (it automatically prioritizes the direct playback streams and adaptive 1080p/720p bitrates, skipping the watermarked fallback).
   - Solves TikTok's JS anti-bot challenge (Proof-of-Work SHA-256) natively in under 2ms (no heavy puppeteer or headless Chrome needed).
   - Auto-converts to universal H.264: TikTok often serves 1080p videos in HEVC / H.265 (which gives a black screen on Windows Media Player, older phones, or smart TVs). js_ydlp detects that, and if FFmpeg is there, it auto-recodes it to standard H.264 (yuv420p + aac with +faststart) so it actually opens and plays in literally any player.
   - Works with all TikTok links: standard links, mobile/short links (`vm.tiktok.com`, `vt.tiktok.com`, `/t/`), and embed URLs.

3. YouTube (Innertube cascade, bot bypass, and sig solver):
   - Doesn't get blocked by the usual bot walls because it cascades through Innertube clients (tries ANDROID first, then falls back to IOS, then WEB) without needing you to log in or pass cookie files.
   - Has its own built-in signature decipher engine (extracts the bytecode operations from YouTube's player JS) and PO-Token support.
   - Full format selection: grab `best`, `worst`, `bestvideo`, `bestaudio`, specific itags, or pass your own filter function.

4. Music downloads with real metadata, cover art, and lyrics:
   - When you download a song, it doesn't just dump raw audio; it queries public music databases (iTunes) to find the actual genre (Dance, Electronic, Pop, etc.), the official album, and the release year.
   - Embeds high-res cover art right into the MP3 container (ID3v2 APIC tag).
   - Writes proper ID3 tags (artist, title, album, year, genre).
   - Automatically searches for lyrics (LRCLIB, with fallback to YouTube captions) and embeds them into the file.
   - Can also generate a synced `.lrc` file right next to your song if you want karaoke-style lyrics on your player (`writeLrc: true`).

5. Streams in chunks directly to disk (zero RAM bloat):
   - Uses Web ReadableStreams and Node streams chunk-by-chunk.
   - Never loads the whole video into RAM (your memory stays at a few KB whether you download a 5MB song or a 50GB video).
   - Saves to a temporary `.part` file first, and only renames it once it's 100% finished.
   - Supports HTTP 206 Range resumption: if your connection drops, it picks up right where it left off instead of starting from zero.
   - Real-time progress updates every 250ms (speed in B/s, ETA, downloaded bytes, percentage, etc.).

6. Modular Ninja builds (keep it tiny):
   - You can compile only what you actually need:
     * `all`: the full bundle with everything (around 66 KB minified).
     * `youtube`: only YouTube and direct streams (around 60 KB, with zero TikTok code inside).
     * `tiktok`: only TikTok and direct streams (around 59 KB, with zero YouTube code inside).
   - Minified with Terser (variable mangling, dead code removal, and 100% of internal comments stripped).
   - Verified target isolation (so you know for sure the separate builds don't drag code from the other platforms).

7. Solid tests and clean standards:
   - 47 automated tests passing out of 47 (`npm test`).
   - Netscape cookie file import/export (`CookieJar`).
   - Apache 2.0 license and Open AI statement included across the codebase.
